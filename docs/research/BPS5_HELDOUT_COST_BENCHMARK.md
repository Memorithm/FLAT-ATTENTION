# BPS-5 — disjoint held-out benchmark and logical resource algebra

Status: **research-only**, deterministic synthetic experiment.
This is a measurement *protocol* and executable candidate, not a
demonstrated power advantage or an FP32-LSTM comparison.

Sources:
- crates/flat-algebraic-attention/src/boolean_benchmark_protocol.rs
- crates/flat-algebraic-attention/examples/bps5_heldout_benchmark.rs

## Scientific question

Does BPS-4 joint gate/topology search generalize to **unseen initial-state
lanes and independently generated inputs**, relative to BPS-3 under
(a) no training and (b) rotation-only training with fixed gates?
Does the sparse BPS-3 implementation avoid recurrent evaluations on
quiet timesteps, and what resource proxy can be reported without
pretending to have measured electricity?

BPS-3, minLSTM and FP32 LSTM are different hypothesis families. This
prototype deliberately compares only like-for-like BPS-3 model families.
FP32 LSTM, minLSTM and classical RNN baselines must be added as an
**independent future comparison with matched dataset, representation,
training budget and hardware**. Never label the rotation-only baseline
as an FP32 LSTM.

## Dataset contract (reproducible)

All inputs are created by a frozen xorshift64 PRNG from an explicit
seed, and all supervision labels are generated by an explicitly
provided frozen BPS-3 teacher. These are **teacher-generated synthetic
targets**, not external real-world labels.

- At most 64 independent episodes, each 1..4096 sampled timesteps.
- Train, validation and test sizes are positive and specified in the
  protocol. Their initial state is a unique 1-hot bit (bit position
  equals episode's global index): no initial state is shared across
  partitions. This proves *source-initial-state disjointness*, not
  statistical independence of synthetic tasks or natural data.
- The PRNG is deterministic and advanced sequentially through all
  episodes. Training targets do not include validation or test labels.
- A sample contains either the zero word or a 1-hot pulse word.
  **Requested occupancy** is the probability of a nonzero sampled
  word; it is **not** the observed rising-event density. Repeated
  high bits do not produce repeated fronts.
- The input baseline is explicitly recorded per episode. A prior
  sampled bit already at 1 does not generate a fabricated rising
  edge. Falling edges re-arm pulses.
- Training selects parameters using only train labels. Validation
  labels are inspected for reporting but never model selection.
  Test labels are first scored after parameters are frozen.

The executable runs 2 teacher scenarios and occupancies of 0%, 10%,
50%, 100% (one pulse-lane configuration), with 8 training episodes,
4 validation episodes, 8 test episodes and 32 steps each. The two
tasks are a **rotated delayed-state propagation** teacher and a
**conditional edge-write** teacher; they are **not** rigorous
selective-copy tasks or proofs of language competence.

## Fairness, metrics and baselines

For every scenario/occupancy, all baselines start from the **same**
student Boolean gate masks and recurrent shift. They share the same
train, validation and test episodes. The methods are:

1. Untrained: retain the frozen initial model.
2. Rotation-only: enumerate the other 63 shifts, select only strict
   improvements in *training* Hamming loss; keep gate masks fixed.
3. Joint BPS-4: jointly optimize shift and unary gate/readout bits,
   with bounded pair-mutation fallback and explicit training budget.

These methods have **different candidate evaluation counts**; those
counts are reported, not disguised as equal training compute. Joint
search may overfit and achieve worse held-out error than rotation-only.
The generator and tests must never assume an improvement.

For method m and split S:

    errors(m,S) =
        sum[episode in S, tick in episode]
            popcount(predicted_output XOR teacher_target)

    opportunities(S) = 64 * total_sampled_ticks(S)

The results contain the integer numerator and denominator rather
than low-precision rounded claims of accuracy.

The benchmark requires the sparse BPS-3 runtime, dense oracle and
event-only temporal scan to agree **bit-for-bit** on each test
episode; otherwise it fails closed. This tests semantic equivalence,
not latency, robustness against distribution shifts or
statistical generalization.

## Additive logical work ledger — NOT physical energy

Let R = (S, E, O, F), where

- S: sampled input 64-bit words,
- E: recurrent transitions actually evaluated on eventful steps,
- O: output 64-bit words emitted,
- F: state bit flips.

The additive operation is component-wise checked addition:

    (S1,E1,O1,F1) + (S2,E2,O2,F2)
      = (S1+S2, E1+E2, O1+O2, F1+F2)

The zero vector is the identity. The implementation rejects u128
overflow rather than wrapping. A user-selected *dimensionless*
projection is:

    proxy(R,w) = wS*S + wE*E + wO*O + wF*F

All four weights are unsigned arbitrary **hypotheses**. This algebra
exposes potential tradeoffs and permits sensitivity analysis; these
weights have **no calibrated unit**, and the projection must never be
presented as joules, pJ, wall-clock latency, actual CPU instructions,
memory bandwidth or physical transitions.

The current sparse executor still inspects every input sample:
E can be much smaller than S without the entire program becoming
event-proportional. In the current generator, occupancy=100% with
a fixed pulse lane may generate only an initial rising edge:
do not equate occupancy with front rate.

## Reproduce the exact deterministic experiment

On a machine with the supported Rust 1.89 toolchain:

    cargo fmt --all -- --check
    cargo clippy -p flat-algebraic-attention --all-targets -- -D warnings
    cargo test -p flat-algebraic-attention boolean_benchmark_protocol
    cargo run -p flat-algebraic-attention --example bps5_heldout_benchmark

The executable writes a header and 24 CSV data rows to stdout:
2 scenarios * 4 occupancies * 3 baselines.
It prints split Hamming losses, test opportunity counts, actual
eventful steps, candidate evaluations, topology choice and logical
work fields. The CSV explicitly records physical_energy_measured=false.

No Python, Torch, TensorFlow, vendor GPU SDK, external dataset or
physical run is necessary for this correctness qualification.
All normal FLAT-ATTENTION whole-workspace CI gates still apply to
the candidate HEAD before merge.

## TDI / RemoteOps physical qualification — still required

This commit **does not** run an unsupervised benchmark or modify
self-hosted services. For physical qualification use
Memorithm/RemoteOps as the sole remote control plane, schedule a
bounded, isolated, read-only measurement window on a named CPU host
and record:

1. Exact repository+binary SHA, compiler flags, CPU model, kernel,
   governor, NUMA affinity and frequency/turbo status.
2. Serialized frozen corpus and checksum; baseline per-episode
   initial state; exact event count E rather than requested occupancy.
3. Repetitions, warmup, per-method p50/p95 latency and throughput,
   process affinity, background workload and temperature.
4. Package and memory energy readings from independently verified
   device sources (if actually available), including counter width,
   wraparound, idle subtraction, attribution uncertainty and units.
5. A negative-control suite where zero events still incur input
   inspection and output emission, and occupancy is never substituted
   for front density.

Only after independent meter calibration should proxy weights be
interpreted as energy-related. Measuring a logical flip or reduced
candidate count does not establish lower joules. Do not claim
superiority over FP32 LSTM/minLSTM until those baselines have been
run on the same registered task and physical device.
